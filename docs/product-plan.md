# Nova 产品方案

> 版本：v1.1　评审稿  
> 日期：2026-10-23  
> 适用工程：`nova-work`（六个独立工程，非 monorepo）  
> 对外应用名 / 安装包名：**DaveBella**　内部产品代号：**Nova**

---

## 1. 结论摘要

Nova 是一套面向线下门店的经营工作台，由六个交付物组成：

| 端 | 角色 | 核心价值 |
|---|---|---|
| 桌面端（Electron） | 店长 / 店员的经营主控台 | 全量经营管理 + AI 经营分析任务 |
| 手机端（Expo / Android） | 店内移动作业 | 随时查货、开单、买单、会员服务 |
| 浏览器插件（Chrome MV3） | 采购 / 商品运营 | 从供应商页面一键采集商品图片与款号 |
| 小程序（Taro / 微信） | 消费者会员 | 查订单、积分、余额、优惠券、活动 |
| POS 服务端（nova-pos-server） | 系统底座 | 订单、库存、会员、营销、数据统一 API |
| 小程序服务端（nova-mall-server） | 会员侧底座 | 会员登录、订单、积分、余额、活动 API |

本版是**单店应用**：不提供多门店切换、门店隔离与跨店报表，所有数据属于同一家门店。

本版三个关键变化：

1. 桌面端新增 **经营分析**：左任务列表 + 右对话，Agent 可调用内置经营工具，产出可预览的报表文件；Agent 以只读账号直连 MySQL 查询真实经营数据，表结构作为 Agent 上下文写入提示词。
2. 桌面端 **数据中心移除全部 AI 分析入口**，数据只做事实呈现；分析能力统一收敛到「经营分析」。
3. 手机端 **彻底移除直连 MySQL**，改为调用 POS API；底部 5 Tab（订单 / 库存 / 买单 / 会员 / 数据），买单仍是最高优先级流程。

产品成功的唯一标准：**店长每天愿意打开它，并且它给出的经营结论可以照着做。**

## 2. 愿景、定位与设计原则

### 2.1 愿景

> 懂我，帮我的经营伙伴。

### 2.2 定位

> 能准确无误地让我高效经营，并能帮我创造生意、帮我做经营诊断的优秀经营伙伴。

拆成三条产品承诺：

- **准确**：每一笔订单、每一件库存、每一分会员余额都可核对；AI 结论必须能追溯到数据。
- **高效**：店长高频动作（买单、查库存、查会员、看今日经营）在 3 步以内完成。
- **创造生意**：不止展示数据，还能给出可执行动作，例如补货、调价、唤醒会员、复盘活动。

### 2.3 设计原则

1. **事实与判断分离**：数据中心只陈述事实；判断、归因、建议只出现在经营分析。
2. **对话即入口，结构即结果**：用户用自然语言提需求，Agent 用固定结构的报告交付，不产出散乱长文。
3. **先给结论，再给证据**：所有分析首屏先给「发生了什么、为什么、建议做什么」。
4. **数据可追溯**：每个数字标注时间范围、统计口径、数据更新时间。
5. **危险动作要确认**：查询自动执行，写操作（改库存、发券、退款）必须二次确认。
6. **端尽其责**：桌面做深度，手机做速度，插件做采集，小程序做会员自助，不互相复制。
7. **一致的设计语言**：shadcn/ui、Lucide 图标、4px 网格、中性色 + 单一品牌色，禁止 emoji 充当图标。

### 2.4 命名与包名

| 项 | 取值 |
|---|---|
| 对外产品名 | DaveBella |
| 内部代号 | Nova |
| 代码目录 | `nova-desktop` / `nova-extension` / `nova-mobile` / `nova-miniapp` / `nova-pos-server` / `nova-mall-server` |
| 桌面 productName | `DaveBella` |
| 桌面 appId | `com.davebella.nova` |

> 工程结构对齐 `nexa-work`：六个目录各自独立安装依赖、独立构建，不使用 monorepo / workspaces。

## 3. 用户与核心场景

### 3.1 角色

| 角色 | 主要诉求 | 主要端 |
|---|---|---|
| 管理员（店长） | 今天生意怎么样、哪里出了问题、成本利润、该怎么调整 | 桌面端、手机端数据 |
| 导购员 | 快速买单、查库存、查会员权益、退换货 | 手机端、桌面端买单 |
| 商品 / 采购 | 从供应商页面采集商品图、核对款号 | 浏览器插件、桌面库存 |
| 会员（消费者） | 查订单、积分、余额、优惠券、活动 | 小程序 |

系统登录身份只有**管理员**与**导购员**两种，注册默认为导购员：

- 管理员：全部功能；可查看进货价、成本、毛利额、毛利率；可配置定时任务、系统设置、操作日志。
- 导购员：买单、订单、库存、会员、数据的日常操作与查询；**进货价、成本、毛利额、毛利率全部不可见**（沿用旧实现的硬编码口径，桌面端与手机端一致）；可发起并直接完成退货/退款。
- 数据接口按角色过滤成本与利润字段，前端不依赖隐藏列做安全边界。

### 3.2 店长的一天（目标体验）

| 时间 | 场景 | Nova 的响应 |
|---|---|---|
| 09:00 | 开店前看昨日经营 | 桌面端「经营分析」查看昨晚 21:20 自动生成的店铺经营日报：销售额、单量、客单价、连带率、毛利率、退款率、会员占比，并给出 3 条待办 |
| 10:30 | 发现某款断码 | 对话问「哪些款断码最严重」，Agent 调库存工具，产出滞销/断码清单 |
| 14:00 | 店员手机开单 | 手机端扫码 → 选会员 → 用券 → 收款 → 成功页 |
| 16:00 | 供应商上新采图 | 插件右键图片 → 核对款号 → 采集，桌面库存立即有图 |
| 21:30 | 闭店复盘 | 桌面端 21:20 已自动生成当日经营日报，右上角消息红点提醒，点开即看异常与明日建议 |

### 3.3 核心 Job To Be Done

1. 当我打开桌面端时，我想在 10 秒内知道今天/近 7 天生意是否正常。
2. 当我要分析一个异常时，我想用一句话拿到结论、证据和动作建议。
3. 当我在店里走动时，我想用手机完成查货、开单、买单、查会员。
4. 当我在供应商网站选货时，我想一键把图片和款号带回系统。
5. 当我是会员时，我想不看店员也能查到订单、积分、余额。

## 5. 桌面端详细设计

### 5.1 全局框架

- 左侧 78px 图标导航栏（macOS 交通灯避让区 28px），图标 + 8px 文案；选中态为品牌色浅底 + 左侧 2px 指示条。顶部为应用图标（购物袋 SVG），底部为设置入口（齿轮图标，打开系统设置 Dialog），不再放用户头像。
- 顶部 56px 工作区头：左侧固定文字 Logo（第一行大字 `Dave & Bella`，第二行灰色小字版本号），随后是当前页面标题与副标题；右侧为刷新、消息（铃铛，有未读时显示红点，点开为消息列表，点击消息跳转到对应任务并标记已读）、个人中心。**不提供门店切换、数据同步状态、全局搜索。**
- 下单/查数等动作在各自页面内完成；数据由服务端同步，无需在头部展示同步状态。
- 内容区留白统一为上下左右各 16px（经营分析、买单、订单、库存、会员、营销、数据全部一致），表格/卡片统一 12px 圆角、1px 边框。
- 窗口最小尺寸 1180 × 760；默认 1440 × 900。
- 通用弹层（操作日志、系统设置、修改密码、退出登录、收款成功等）使用 Dialog；订单明细、对账、订单商品、会员详情与经营分析产物使用右侧抽屉，抽屉统一从应用顶部拉出并覆盖应用整高（不是从标题栏下方的局部面板展开）。

### 5.2 经营分析（新增核心模块）

#### 5.2.1 布局

```
┌──────────┬──────────────────────────────┬──────────────────────┐
│ 任务列表  │  任务头（标题/状态/时间/操作）      │  产物抽屉（可收起）      │
│ 280px    │  消息流（用户/Agent/工具/产物）    │  预览区 + 文件树 200px  │
│          │  输入区（附件/发送/停止）          │                      │
└──────────┴──────────────────────────────┴──────────────────────┘
```

- 左栏：顶部仅「任务」标题 + 任务总数；**不提供任务搜索、不提供顶部「新建」按钮**。任务按固定顺序分为三个分组，**分组标题可点击折叠 / 展开**（折叠状态在本次运行内保持）：
  1. **经营分析**（预设三个周期任务，见 5.2.2）：店铺经营日报、店铺经营周报、店铺经营月报；每项展示状态点、最近执行时间、数据范围与「每晚 21:20 / 每周一 10:10 / 每月 1 日 10:20 自动执行」。
  2. **自由对话**：用户手动发起的一次性分析/追问会话。
  3. **归档任务**：已归档的历史任务，只读，可恢复。
- 新建入口：仅「自由对话」分组标题右侧提供一个「+」图标按钮，点击新建「新对话」并选中；「经营分析」与「归档任务」两个分组不提供新建能力。
- 任务项含状态点（运行中 / 已完成 / 失败）与最近执行时间；点击切换右侧任务详情。
- 右栏：任务标题 + 状态 + 数据范围；消息流；底部输入框支持回车发送、Shift+Enter 换行、停止生成、重新生成。
- 产物抽屉：默认收起；当任务首次产出文件时，右侧滑出，宽度 720px，可拖拽调宽，支持最大化；左侧预览，右侧文件树；支持在 Finder 中显示。
- 空态：展示 4 个推荐任务卡，点击即创建会话并自动执行。

#### 5.2.2 任务类型

| 类型 | 触发 | 执行时间 / 数据范围 | 交付物 |
|---|---|---|---|
| 店铺经营日报 | 定时（可暂停） / 手动 | 每晚 **21:20**；当日 + 对比昨日/上周同日 | 经营日报（HTML）+ 指标明细（CSV） |
| 店铺经营周报 | 定时（可暂停） / 手动 | 每周一 **10:10**；上周一 ~ 上周日 | 经营周报（HTML + CSV） |
| 店铺经营月报 | 定时（可暂停） / 手动 | 每月 1 号 **10:20**；上月 1 号 ~ 上月最后一天 | 经营月报（HTML + CSV） |
| 自由对话分析 | 用户一句话 | 由 Agent 确认 | 按需（可无产物） |
| 库存健康诊断 | 手动（自由对话） | 近 30 天 | 断码/滞销/周转清单（HTML + CSV） |
| 会员复购分析 | 手动（自由对话） | 近 90 天 | 分层与唤醒建议（HTML） |
| 活动复盘 | 自由对话（手动） | 活动周期 + 对比周期 | 复盘报告（HTML） |

> 三个周期任务固定在「经营分析」分组，不可删除，可暂停；执行时间默认如上，**管理员可在系统设置 → 任务 → 定时任务执行时间中修改**；系统休眠错过执行时，唤醒后补跑一次。

#### 5.2.3 消息通知

- 定时任务生成报告后，写入一条系统消息，并在右上角铃铛显示红点。
- 点击铃铛展开消息列表：标题（如「店铺经营日报已生成」）、摘要、时间；未读项带红点。
- 点击任意消息 → 直接跳转到对应任务详情，同时该消息标记已读；未读清零后红点消失。
- 支持「全部标记为已读」；失败任务的消息带失败原因与重新生成入口。

#### 5.2.4 会话消息类型

1. **用户消息**：文本 + 可选附件（图片/CSV）。
2. **Agent 文本**：Markdown 渲染，支持表格、指标卡、引用块。
3. **思考/过程**：默认折叠，展示「正在查询…」等 1 行状态；可展开看工具轨迹。
4. **工具调用卡**：工具名、参数摘要、耗时、返回条数、展开看原始结果（截断）。
5. **产物卡**：文件图标、标题、类型、大小、生成时间；点击打开抽屉；「在文件夹中显示」。
6. **确认卡**：写操作前出现，展示影响范围与「确认执行 / 取消」，超时自动取消。
7. **错误卡**：错误原因、可重试按钮、错误码。

#### 5.2.5 交互细节

- 新建自由对话：点击「自由对话」分组标题右侧的「+」直接创建「新对话」并选中；标题可自动生成，数据范围在首轮对话中确认；创建后在 workspace 建目录。周期任务与归档任务不提供新建入口。
- 发送消息：若任务未运行则启动 Agent；运行中禁止并发，只能追加排队或停止。
- 停止：中断当前 LLM 流与工具执行，消息标记「已停止」，可继续对话。
- 重试：沿用原始用户消息，新建一轮 run，不覆盖历史。
- 删除任务：二次确认；本地会话与 workspace 一并删除（可配置保留 30 天）。
- 自动任务：按 cron 到点自动创建会话并执行（日报 21:20 / 周报周一 10:10 / 月报每月 1 号 10:20），完成后写入消息并在右上角铃铛提示；失败重试 1 次并记录原因。
- 数据时间：所有报告标题下方固定展示「数据范围 / 生成时间 / 数据截止」。

#### 5.2.6 Agent 行为规范

- 第一次回复必须先确认口径：若用户未给时间范围，默认「今天」并明确写出。
- 任何结论必须绑定工具数据；无数据时回答「当前范围内没有数据」，禁止编造。
- 报告结构固定：结论摘要（3 条以内）→ 核心指标 → 归因 → 风险与异常 → 行动建议（按优先级，含负责人建议与时间）。
- 数字单位统一：金额 `¥`、百分比 1 位小数、同比/环比标注基准。
- 生成文件必须写入当前会话 workspace，并在消息中发布产物卡。
- 单次回复不超过 600 字；长内容进报告文件。
- **数据库即上下文**：系统提示词内置本店 MySQL 的真实表结构（表名、字段、类型、注释、关键枚举与常用关联关系），Agent 优先用内置工具查询；工具覆盖不到的问题，可基于表结构生成只读 SQL，由主进程用只读账号直连 MySQL 执行并限制条数与超时。表结构在会话启动时注入，库表变更后下次会话自动刷新。

#### 5.2.7 数据库上下文注入

- 数据源：Agent 通过只读账号直连 MySQL 查询真实业务数据（订单、订单明细、商品、库存、会员等），不做本地业务缓存；表结构由主进程读取 `information_schema` 生成。
- 注入内容：
  - 表清单：表名 + 中文注释 + 预估行数。
  - 字段清单：字段名、类型、是否可空、默认值、注释。
  - 关联关系：外键与业务约定（如订单表 `orderSn` ↔ 明细表 `orderSn`）。
  - 枚举字典：订单状态、支付方式、库存状态、会员等级等取值。
- 组织方式：按业务域分组（订单 / 库存 / 会员 / 营销 / 财务），生成精简 Markdown，控制在 6k tokens 内；超长时只注入与当前任务相关的域。
- 安全边界：只读账号；仅允许 `SELECT`，禁止 DDL/DML/多语句；查询自动 `LIMIT 200`、10s 超时；成本与利润字段按角色过滤，导购员不可见；会员手机号完整返回；查询全部记录审计日志。
- 运营方式：桌面端「系统设置 → 数据」展示表结构快照的更新时间与表数量，支持手动刷新；报告标注数据查询时间。

### 5.3 买单

- 三栏：左「商品录入」、中「待售清单」、右「结算面板」。
- 商品录入支持扫码枪（全局监听回车）、手输条码、按款号检索；重复扫码累加数量。顶部不设「扫码」「加入」按钮，扫描/手输后回车即入清单。
- 待售清单列：商品、单价、数量、**折扣**、小计；折扣默认 `6.0`（即 6 折），单元格内直接点击修改，修改后实时重算小计与应收。
- 结算面板：会员（手机号/姓名）→ 积分抵扣 / 余额抵扣 / 优惠券 / 整单折扣 → 应收金额放在本组最上方；然后新增导购员下拉选择框、备注输入框；最后支付方式改为**下拉选择**（微信/支付宝/现金/银行卡/其他），无组合支付选项；实收输入框右侧不展示「找零 ¥0.00」，找零仅在收款成功页展示。「实收」标签与输入框同行，标签固定单行不换行，输入框自适应剩余宽度。
- 提交前校验：库存、会员余额、券可用性、折扣权限；提交幂等。
- 成功后：成功页展示找零、积分变动、余额变动；支持打印小票、继续开单。
- 异常：库存不足提示具体 SKU；支付金额不一致需二次确认；网络失败保留单据并可重试。
- 挂单 / 取单：待售清单右上角提供「挂单」，把当前清单、会员、导购员整体存入本机缓存并清空清单，不提交服务端、不占用库存；有挂单时显示「恢复挂单」，点击取回。若当前清单非空，先二次确认再覆盖；正式收款成功后清除挂单。仅保留最近一笔挂单。

### 5.4 订单中心

- 概览卡：订单数、商品数、订单金额、余额消耗、充值金额。
- 筛选：日期区间（单个区间日历组件，一次选择开始与结束日期）、订单号、会员手机号、导购（下拉选择）、支付方式（下拉选择）；删除原来的状态分段切换；右侧两个按钮：「对账」与「订单商品」。
- 列表工具栏仅保留查询/重置等操作，**不提供导入订单**；导出入口只在订单明细抽屉与「订单商品」抽屉内。
- 列表：订单号、时间、商品数、原价、实收、支付方式、导购、状态、打印状态；底部分页（总数 + 页码）。
- 详情：商品明细、优惠明细、支付信息；操作：改单、退货、换货、打印。
- 对账抽屉：当日订单列表，每条订单带「确认到账」按钮；顶部汇总已确认金额/待确认金额/待确认单数；支持全部确认；导出对账明细。
- **订单商品抽屉**：入口为筛选栏「对账」右侧的「订单商品」按钮；抽屉内只有一个订单日期区间选择框（开始/结束）+ 查询 + 导出；查询结果以**组合表格**展示一单多商品：订单号 / 下单时间 / 实收 / 件数 用 `rowspan` 按订单合并，商品 / SKU / 数量 / 小计 逐行展开；导出按当前区间导出全部订单商品。
- 商品明细抽屉：按 SKU 维度统计销量、销售额、毛利率（仅管理员可见）；抽屉右上角提供「导出」，按当前筛选条件导出 CSV/XLSX。
- 所有抽屉（商品明细、对账、订单商品）均从**应用顶部拉出**，覆盖顶部标题栏、上下与应用外框齐平，不从头下方的局部区域开始。

### 5.5 库存中心

- 概览：款式总数、库存总量、已售总数、断码款数。
- 列表：图片、款号、SKU、品名、颜色、尺码、库存、零售价、成本（仅管理员可见）、最近销售时间；**底部分页**（共 N 条 + 页码 + 上一页/下一页）。
- 筛选栏单行布局：左「全部库存/断码/热销」单选组 + 款号/SKU/品名搜索框；右「商品流水」按钮 + 「批量操作」下拉菜单；下拉菜单包含「批量入库、批量退库、单个入库」三项；删除「下载模板」按钮与额外过滤按钮。
- 商品流水：独立页面打开，入库、销售、退货、调拨、盘点；按时间倒序，支持导出。
- 断码 / 热销：单选切换，断码按缺码数排序，热销按销量/售罄率排序。
- 图片：九宫格预览、上传、替换、删除；插件采集的图片**直接生效**，服务端落盘 `<款号>.jpg` 并写入库存表 `image` 字段，同款直接覆盖，不进入待确认队列。

### 5.6 会员中心

- 概览卡：会员总数、超级会员总数、会员余额。
- 筛选栏：姓名/手机号搜索框、等级下拉选择、创建时间（与订单页同款**日期区间选择器**，一次选择开始与结束日期）；删除「最近到店」和「有余额」按钮；删除右侧「会员充值」入口。
- 列表：头像、姓名、手机号、等级、积分、余额、累计消费、最近到店、注册时间；**底部分页**（共 N 条 + 页码 + 上一页/下一页）。
- 页面不再保留常驻的右侧会员详情区域；操作列为「详情 / 编辑 / 充值」三个入口，点击「详情」才从右侧滑出会员详情抽屉（宽 480px，从应用顶部拉出、覆盖应用整高）。
- 详情抽屉：会员基本信息、积分/余额/累计消费/订单数四项指标、订单/积分/余额/优惠券分段、订单列表；底部固定「编辑」「充值」。
- 充值：入口在会员抽屉底部与列表行内「充值」；金额、赠送金额、支付方式、备注；生成余额流水。
- 积分调整：增减、原因、操作人；写操作日志。
- 券：可用/已用/过期；支持手动发券（P1）。
- 合并/去重：手机号唯一；异常提示。

### 5.7 营销中心

- 查询条件：活动名称输入框、活动时间（与订单页同款**日期区间选择器**）、活动类型下拉（全部类型 / 满减 / 优惠券 / 预售 / 折扣）+ 查询 / 重置；**不提供状态 Tab 切换**。
- 页面级操作：查询栏右侧仅保留「新建活动」，**不提供「优惠券」入口**。
- 活动列表：默认表格/列表视图（不使用卡片流），列含名称、类型、时间、状态（未开始/进行中/已结束/已下线）、参与人数、核销数、带动销售额；表格末列表头统一为「操作」。
- 行内操作固定为「详情 / 编辑 / 下线 / 删除」，**不提供优惠券与复盘操作**；下线、删除需二次确认并说明影响，删除仅允许未开始或已下线活动。

## 6. 手机端详细设计

### 6.1 目标机型与适配

| 机型 | 逻辑分辨率 | 关键点 |
|---|---|---|
| iPhone 14 | 390 × 844 | 安全区、底部 Home Indicator |
| 华为 P40 | 360 × 780 | Android 字体缩放、虚拟导航键 |
| 华为 Mate 60 | 360 × 780+ | 高刷、圆角、状态栏避让 |

适配规则：

- 使用 `useWindowDimensions` + `react-native-safe-area-context`，禁止写死 375。
- 最小点击区 44 × 44；表格类改为卡片列表。
- 字体缩放上限 1.2，超出截断不换行破坏布局。
- 横屏不强制支持；买单页锁定竖屏。

### 6.2 导航

底部 5 Tab：订单 / 库存 / 买单 / 会员 / 数据。买单位于中间，图标更大、选中态为品牌色圆形底。顶部左侧为应用图标 + 当前页面标题（图标在标题前），右侧头像进入「我的」（账号、设置、退出登录）。不提供营销入口与营销页面。

### 6.3 买单（核心）

流程：扫码/输入 → 待售清单 → 选会员 → 优惠 → 支付 → 成功。

- **扫码页**：相机扫码 + 手输条码；连续扫码；扫到不存在/无库存给出明确提示。
- **待售清单**：商品卡（图、名称、颜色尺码、单价、数量步进器、小计）；滑动删除；底部汇总（件数、原价、优惠、应收）。
- **会员**：手机号搜索；展示等级、积分、余额、可用券；一键使用积分/余额。
- **优惠**：整单折扣（权限内）、优惠券选择（展示不可用原因）。
- **支付**：支付方式分段选择；实收金额快捷填充（应收/整百）；现金找零；备注；提交防抖。
- **成功页**：大字实收、找零、积分/余额变动；打印小票（蓝牙，P1）；继续开单。
- **异常**：网络失败保留单据 + 同幂等键重试；库存冲突提示；支付超时状态查询。

### 6.4 订单

- 列表：今日/近 7 天/自定义；状态筛选；搜索订单号/手机号。
- 卡片：订单号、时间、件数、实收、支付方式、状态。
- 详情：商品、优惠、支付、会员；操作：退货、换货（复用桌面规则）、打印。
- 退货：选择商品与数量 → 退货原因 → 退款方式 → 确认；退款金额自动计算；**导购员可直接完成退货/退款**，无需管理员二次确认。

### 6.5 库存

- 搜索款号/SKU/品名；扫码直达 SKU。
- 列表卡片：图片、款号、品名、颜色尺码、库存、零售价；库存为 0 红色。
- 详情：各尺码库存矩阵、近 30 天销量、流水入口。
- 流水：时间、类型、数量、前后库存、关联单号。

### 6.6 会员

- 搜索手机号/姓名；列表卡片：姓名、手机号、等级、积分、余额、最近到店。
- 详情：权益概览、订单、积分、余额、优惠券。
- 充值：金额、赠送、支付方式；提交后展示新余额。

### 6.7 数据

- 今日概览：销售额、单量、客单价、连带率、退款额；对比昨日。
- 趋势：近 7 天/30 天柱线图。
- 排行：畅销 Top 5。
- 只读事实，不提供 AI 分析、不提供导购业绩；底部入口「去桌面端做深度分析」。

### 6.8 我的

- 账号信息、角色、版本。
- 设置：API 地址（仅管理员可见）、清缓存、检查更新。
- 退出登录。

## 7. 浏览器插件详细设计

### 7.1 使用流程

1. 插件使用门店账号登录（调用 nova-pos-server 鉴权接口），获取长期 token 存 `chrome.storage.local`；不再需要桌面端生成配对码。
2. 在供应商商品页，右键商品图片，菜单出现「采集图片到 Nova」。
3. 点击后页面右上角出现浮层：
   - 图片预览（当前右键图）
   - 识别到的款号（可编辑输入框）
   - 来源域名
   - 按钮「取消」「采集」
4. 确认后上传，成功 Toast「已采集到 Nova」，失败给出原因与重试。
5. 上传成功即生效：服务端保存 `<款号>.jpg` 并写入 MySQL 库存表 `image` 字段（按款号覆盖同款全部 SKU），桌面与手机库存刷新后立即可见，无需审核。

### 7.2 款号识别策略

1. 页面结构化数据（JSON-LD / meta）中的 `sku` / `productID`。
2. 常见文本模式：`款号：XXXX`、`货号：XXXX`、`商品编码：XXXX`。
3. 面包屑 / 标题中的字母数字组合（长度 4–20，含至少 1 位数字）。
4. 全部失败则输入框为空并聚焦，提示「请手动填写款号」。

支持在 Options 中按域名配置 CSS 选择器覆盖规则。

### 7.3 状态与异常

| 状态 | 表现 |
|---|---|
| 未配对 | 浮层提示「请先在插件设置中完成配对」，提供跳转 |
| 未识别款号 | 输入框红色边框 + 提示 |
| 图片过大 | 前端压缩到 ≤ 2MB，最长边 2000px |
| 上传失败 | 保留浮层与输入内容，可重试 |
| 重复采集 | 同款已有图片时直接覆盖，Toast 提示「已更新图片」 |

### 7.4 安全

- 仅上传用户主动右键的图片，不抓取页面其他内容。
- Token 绑定门店与操作人，可随时在桌面端撤销。
- 上传接口校验 MIME、大小、token，服务端落盘并写入库存表图片字段，记录采集日志。

## 8. 小程序详细设计

### 8.1 页面

## 9. 服务端产品规则

### 9.1 POS 服务端

- 统一响应：`{ code: 0, message: "ok", data, traceId }`；业务错误 `code != 0`。
- 鉴权：登录换 JWT（8 小时），刷新 token（30 天）；请求头 `Authorization: Bearer`。
- 单店上下文：系统固定唯一门店，token 不再携带 `storeId`，查询不需要门店过滤参数。
- 幂等：`POST /buy/submit` 必须带 `Idempotency-Key`，同键 24 小时内返回同一结果。
- 审计：所有写操作记录操作日志（操作人、类型、对象、前后值、客户端版本、系统）。
- 数据一致性：订单提交在单事务内完成订单、明细、库存扣减、会员积分/余额、流水；失败全回滚。
- 上传：白名单 MIME（jpg/png/webp），≤ 10MB，文件名清洗，按 `yyyy/MM/<uuid>.<ext>` 存储。

### 9.2 小程序服务端

- 独立部署、独立数据库账号（只读 + 会员写权限边界）。
- 仅暴露会员自助所需接口；不返回成本、毛利、导购等敏感字段。
- 微信登录态校验；手机号绑定后签发业务 token。

### 9.3 AI 相关下线

- 删除 `/data/analysis` 路由与实现。
- 删除服务端 AI Key、提示词、模型调用依赖。
- 旧客户端调用返回 410，并提示升级。

## 10. 设计规范

### 10.1 色彩

| 用途 | 亮色 | 暗色 |
|---|---|---|
| 品牌主色 | `#4F46E5`（indigo-600） | `#6366F1` |

| 警告 | `#D97706` | `#F59E0B` |
| 危险 | `#DC2626` | `#EF4444` |

### 10.2 字体与间距

- 字体：`Inter, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 字号：12 / 13 / 14 / 16 / 20 / 24 / 32；正文 14，表格 13，标题 20。
- 行高：1.5；数字使用 `tabular-nums`。
- 间距：4 的倍数；卡片内 16/20，页面 24。
- 圆角：控件 8，卡片 12，弹层 16，头像全圆。

### 10.3 组件

- shadcn/ui（new-york，neutral）：Button、Input、Table、Dialog、DropdownMenu、Tabs、Badge、Card、Sheet、Tooltip、ScrollArea、Progress、Skeleton、Toast。
- 图标统一 Lucide React，尺寸 16/18/20，禁止 emoji 与手写 SVG 图标。
- 图表：Recharts；颜色使用品牌色 + 中性灰，最多 6 色。
- 空态：图标 + 一句说明 + 一个主操作。
- 加载：骨架屏优先，超过 300ms 才显示。

### 10.4 文案

- 动词开头、结果导向：「生成今日日报」而不是「日报生成功能」。
- 错误文案三段式：发生了什么 + 为什么 + 怎么办。
- 不使用感叹号堆叠；不使用「智能」「赋能」等空词。
