从冷启动到订单落单

手机端启动、登录、订单首页加载的完整时序，以及买单 / 修改订单 / 退货 / 换货四个关键流程的交互逻辑图。详细文字版见同目录 nova-mobile-architecture.md。

React Native · Expo 58expo-routerZustand + TanStack Querynova-pos-server
01

启动 → 登录 → 订单首页

根布局先用 SecureStore 恢复会话；无 token 时进入登录分支，登录成功后写回会话并跳转订单页；订单页并行拉取列表与统计。

冷启动与会话恢复时序

时段自上而下；虚线为返回消息，紫色为登录成功的会话返回，蓝色为 HTTP 调用。

内部调用HTTP登录成功返回

启动与鉴权分支

登录只发生在「无 token」分支；登录接口返回 401 时不触发全局登出，避免死循环。

02

买单：从加购到落单

购物车状态由 Zustand 持有，价格全部由纯函数 calculatePricing 推导；提交后服务端事务写入订单、库存流水与会员资产。

买单主链路

紫色为最终落单请求；失败统一走 Toast，不再在页面内渲染红字。

03

修改订单 / 退货 / 换货

三者都从订单详情进入；写操作成功后统一失效订单相关缓存并返回列表。已对账（orderStatus = checked）订单只允许修改备注。

修改订单

管理员可选导购；非管理员固定原导购。金额与手机号在锁定态下不可编辑。

退货

可退商品为明细中 counts > 0 的行；退款去向可选原路退回或退回余额。

换货

换入商品通过条码查询加入；售价按吊牌价 6 折，差价支持补差 / 退差与退回余额。

04

前端分层

页面只依赖 store、pricing 与 pos 函数；请求细节收敛在 api.ts。主题、Toast 与扫码是横切能力。

模块依赖

横切能力：主题 / 字号、全局 Toast、扫码覆盖层
