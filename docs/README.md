## 原型

打开 [demo/index.html](../demo/index.html) 后可在顶部切换：

- 桌面端：经营分析（任务 + 对话 + 产物抽屉）、买单、订单、库存、会员、营销、数据、个人中心 Dialog、系统设置（DeepSeek）。
- 手机端：5 Tab、买单全流程、三机型尺寸说明。
- 浏览器插件：右键采集 + 右上角款号核对浮层。
- 小程序：新版 3 Tab 会员端（品牌红主调；首页免登录，含活动 Banner / 主营类目图卡 / 品牌价值三块；发现签到·抽奖·积分兑换；我的会员自助），见 [demo/miniapp.html](../demo/miniapp.html)。

## 本次评审重点

1. 六个独立工程目录（nova-desktop / nova-extension / nova-mobile / nova-miniapp / nova-pos-server / nova-mall-server），不使用 monorepo，是否可以接受。
2. 单店定位：删除门店切换、门店隔离与跨店报表，仅保留一个门店上下文。
3. 桌面端默认首页是否为经营分析；数据中心是否完全移除 AI 与导购业绩。
4. 个人中心四项（操作日志 / 系统设置 / 修改密码 / 退出登录）全部 Dialog 的交互是否符合预期。
5. 数据访问分工：桌面 / 插件 / 手机的业务逻辑全部调用 nova-pos-server；Agent 相关走桌面主进程 IPC，由主进程用只读账号直连 MySQL 查询（仅 SELECT），工具未覆盖时生成只读 SQL；经营分析直接基于真实订单/库存/会员数据。
6. 手机端 5 Tab：订单 / 库存 / 买单 / 会员 / 数据，无营销；买单居中；顶部 Logo + 页面标题。
7. 桌面端头部：无门店切换、无同步状态、无全局搜索；left rail 顶部购物袋图标、底部设置入口（无用户头像）；文字 Logo 两行；内容区统一 16px 边距。
8. 订单页 5 张指标卡与筛选（导购/支付方式下拉、区间日历、对账抽屉、「订单商品」抽屉用组合表格展示一单多商品并可导出）；无导入，导出仅在商品明细/订单商品抽屉；订单与会员抽屉从应用顶部拉出、覆盖应用整高；库存单行筛选 + 批量操作下拉 + 底部分页；会员 3 张卡、创建时间为区间选择器、无右侧常驻详情、仅「详情」打开抽屉并在操作列提供「编辑 / 充值」、底部分页；营销页列表化，查询项为活动名称 / 活动时间区间 / 活动类型，无状态 Tab，操作列为「详情 / 编辑 / 下线 / 删除」，无优惠券与复盘；数据页为 6 项指标卡 + 店铺营业额按月/按天切换，无导购业绩与右侧模块。
9. 系统设置分「通用 / 任务 / 模型 / 数据」四个 Tab（880 × 640，左侧导航，修改即自动保存、无取消/保存）：通用含外观三卡（跟随系统/亮色/暗黑）、字号三卡、开机自启，无门店名、无语言；任务含定时任务执行时间与通知（桌面通知、提示音）；数据无「自动同步」；无「采集授权」（插件采集走服务端接口）。
10. 买单页：待售清单含折扣列（默认 6.0，可就地修改）、支付方式为下拉、实收后无找零文案、顶部无「扫码 / 加入」按钮；清单右上角提供「挂单」，有挂单时显示「恢复挂单」，取单时清单非空需二次确认，挂单仅存本机、不占用库存。
11. 插件采集：右键菜单 + 页面右上角浮层 + 款号可编辑确认；采集直接生效，`/inventory/uploadImage` 落盘 `<款号>.jpg` 并按款号写入 MySQL 库存表 `image` 字段（同款覆盖，不进入待确认队列）。
12. 经营分析左侧任务无搜索、无顶部新建按钮，固定三组（经营分析 / 自由对话 / 归档任务），组标题可点击折叠 / 展开；仅「自由对话」组标题右侧提供「+」新建对话；经营分析预设日报 / 周报 / 月报（21:20 / 周一 10:10 / 每月 1 号 10:20）；报告生成后右上角铃铛红点，消息点击跳转任务详情并标记已读。
13. 登录 / 注册页：启动即全屏展示，左侧品牌区 + 右侧表单；登录为用户名 + 密码；注册仅用户名、姓名、密码、确认密码四个字段，密码不一致即时提示；退出登录回到登录页。
14. 角色只有管理员 / 导购员两种，注册默认导购员；导购员不可见进货价、成本、毛利额、毛利率（沿用旧实现硬编码口径，桌面与手机一致），且可直接完成退货 / 退款；成本字段由接口按角色过滤。
15. 实施顺序：六工程与 npm 脚本 → 平迁并优化两个服务端 → 桌面端（含登录注册）→ 插件端 → 手机端 → 小程序端，最后统一打包。
16. 三个周期任务的执行时间可改：默认 21:20 / 周一 10:10 / 每月 1 号 10:20，管理员可在系统设置 → 任务 → 定时任务执行时间中调整。
17. 会员手机号在桌面端、手机端、小程序与导出结果中全部完整展示，不做脱敏（仅密码、API Key 不落明文）。
18. 操作日志：日期为区间选择器（与订单页同款）、按操作类型筛选，表格分页，底部仅「关闭」，不提供导出。

## 实施计划评审要点

编码前请重点确认 [实施计划与组件方案](./implementation-plan.md)：

1. **视觉落地**：demo 元素到 shadcn / AI Elements 的映射是否完整（§3），token、圆角、字号方案是否认可（§2）。
2. **组件划分**：分层规则、共享组件契约、页面组件树是否符合你的组件化预期（§5、§6）。
3. **Agent 边界**：从 nexa 照搬 / 重写 / 删除的清单是否同意（§7.1），AI Elements 补齐与去 AI SDK 依赖方案是否可行（§7.4）。
4. **质量门禁**：TS strict、组件规则 R1–R11、视觉验收与测试清单是否足够严格（§10）。
5. **阶段与评审门**：D0–D5 的切分与每关交付是否可接受（§11）。
6. **旧代码迁移边界**：旧桌面端是 antd + table-render，哪些逻辑复用、哪些 UI 按 demo 重写、哪些直接删除（§16 文件级映射），以及禁止迁移清单是否认可。
7. **待确认决策**：§12.1 的 D1–D13 需逐项给出结论，尤其是暗黑主题、图表实现、商品流水呈现、订单改单/商品明细、字号缩放。
